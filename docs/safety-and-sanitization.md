# Safety And Sanitization

## Public Starter Rule

Treat this repository as public.

Do not put private or confidential material into it.

## Do Not Include

- personal profiles
- customer records
- company data
- internal project logs
- financial data
- credentials
- tokens
- private workflows
- proprietary teaching or training materials
- real source assets

## Demo Rules

Public demos should be fictional.

Good demo topics:

- weekly report from fictional notes
- personal planning
- public concept explanation
- fictional research synthesis

Avoid demo topics close to private business operations, customer relationships, internal training, or confidential product strategy.

## Before Publishing

Check for:

- `.DS_Store`
- temporary files
- hidden caches
- private names
- internal paths
- API keys
- secrets
- screenshots containing private data
- documents copied from a private workspace

## Principle

If a file requires explanation like "this is safe because I removed the obvious names", it probably should not be public in the first release.
